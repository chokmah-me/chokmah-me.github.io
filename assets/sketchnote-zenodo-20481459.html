THREE-LAYER CONTEXT

Claude Code playbook v4.4.0

1 June 2026 · playbook

Token spend is a context problem with three layers, not a single shorter prompt.

KEY INSIGHT

Token-efficient Claude Code work is agentic pattern plus context control plus supply-chain hardening. Compression is one layer, not the whole playbook.

THE THREE LAYERS

Layer 1
what the session always holds
Layer 2
path-scoped rules
Layer 3
Headroom compression

Path-scoped rules keep a file's instructions off unrelated turns. Headroom compresses what remains. Agentic patterns decide when a subagent is cheaper than a long thread.

ALSO IN v4.4.0

Supply-chain hardening: what the agent is allowed to fetch and run is part of the token design, because a poisoned tool burns the context and the repo.

LIMIT

A playbook, not a measured token audit of a client repo. No savings percentage is claimed on this board.

WHAT EACH LAYER STOPS

  • Always-on context: instructions that must survive every turn, and nothing else.
  • Path-scoped rules: a file's rules stay off unrelated paths.
  • Headroom: compression of what the first two layers still left in the window.
  • Supply chain: a fetched tool can spend the window and change the repo. Hardening is part of the same design.
