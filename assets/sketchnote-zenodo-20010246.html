FAST16 AS A SECOND-ORDER SUBVERSION

nth-order attacks · kernel filter · engineering simulation

Daniyel Yaacov Bilar · Chokmah LLC · 3 May 2026 · v1.3

The FPU is the payload; the filesystem is the hop.

PROBLEM

SentinelOne (April 2026) disclosed fast16, compiled August 2005: kernel-mode filesystem filtering that corrupts floating-point in engineering codes. The mechanism was described; the attack class was not.

KEY INSIGHT

INSIGHT

Second-order subversion: two ancillary hops (OS filesystem stack, then the simulation tool) to reach the high-precision end system. The wormlet is delivery, not a hop. One order below Thompson's compiler trojan, and quieter: runtime, no on-disk source trace.

METHOD

Apply Bilar 2009 nth-order / HOT taxonomy. Map Stuxnet, dr0wned, FLAW3D at the same order in other substrates. Prefetcher disable, explorer.exe delay, 18-product AV check from the source report.

FORMAL CORE

order = count of ancillary systems on the path to the end system

RESULTS

Defenses follow the class: hardware-rooted driver attestation, diverse independent toolchains on validation hosts, air-gapped reference baselines. Reproducible builds catch Thompson; they miss fast16.

LIMITS

Classification paper, not a new exploit. Relies on the SentinelOne technical report for mechanism detail.
