THREE REGIMES, THREE BOUNDS

Capability attestation for autonomous agents

11 May 2026 · preprint

Benchmark attestation is a Regime 2 method pointed at Regime 3 agents.

KEY INSIGHT

There is no single method to attest a claimed capability. The query bound depends on the computational model and on whether the agent may be adversarial.

THE BOUNDS ON THE LANDING

Regime 1 deterministic · n = O((d/ε) log(1/ε) + (1/ε) log(1/δ))
Regime 2 cooperative stochastic · n = Θ((1/ε²) log(1/δ))
Regime 3 adversarial · PRF embedding blocks polynomial adaptive queries

Also: no non-adaptive protocol with a fixed query set known to the adversary succeeds.

CATEGORY ERROR

Fixed benchmarks are cooperative statistical tools. API and tool-using agents sit in Regime 3.

NOT THE GHIDRA PLUGIN

This paper states the regimes and the bounds. The plugin only stamps the labels onto firmware functions.

WHICH TOOL BELONGS WHERE

  • Regime 1, deterministic: VC dimension sets the query count.
  • Regime 2, cooperative stochastic, fixed configuration: Chernoff bounds.
  • Regime 3, adversary picks the worst pair: non-adaptive fixed query sets fail, and PRF embedding blocks polynomial adaptive protocols.
  • A benchmark is a Regime 2 tool. Pointing it at an untrusted API agent is the category error.
