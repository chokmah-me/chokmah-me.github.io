COMPILER AS NUM: SHADOW-PRICE INLINING

Dual decomposition on the MIR lightweight JIT

Daniyel Yaacov Bilar · Chokmah LLC · February–March 2026

Inlining is a resource price, not a boolean.

PROBLEM

Bilar (2007) said executables are engineered optimization. Compilers still treat inlining as local heuristics. Network Utility Maximization already has a language for that: dual decomposition and shadow prices.

KEY INSIGHT

INSIGHT

A JIT doing profile-guided optimization implements dual decomposition: a runtime coordinator sets λ, passes set thresholds. Test it on MIR.

METHOD

Three phases: synthetic profiling (750 scenarios: 50 functions × 5 sizes × 3 opt levels); shadow-price mutation of MIR_CALL; wall-clock four-condition benchmark (baseline, uniform, skewed, perturbed).

FORMAL CORE

λ adjusts inlining threshold · dual decomposition

RESULTS

Spearman ρ = 0.71 (p < 10^−14). Cohen's d = 2.00 hot vs cold. 98.4% perturbation hold. Shadow-price optimization matches inline-all with about half the mutations.

LIMITS

MIR, not LLVM. Synthetic frequencies in phase 1. Software zip is a separate concept from the papers.
